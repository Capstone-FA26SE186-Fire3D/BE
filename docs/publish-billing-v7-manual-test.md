# Manual acceptance: billing v7, publish and reporting

Use Swagger on the artifact from this branch; verify `/health/version` first. These are deployment acceptance steps, not evidence they have run against Supabase or a real provider. Apply additive migrations, update **all** API/worker instances and verify restricted-role grants before enabling new sales. Keep existing legacy checkout recovery running. Never reset application data to run these checks.

1. **Admin quota policy:** `POST /api/admin/billing/quota-policies` with `quotaUnit`, timezone-qualified `effectiveFrom`, optional `effectiveUntil` covering the entire planned term. Verify 201 and GET list/detail. Policy is immutable; a change needs another version. No business policy/value is seeded.
2. **Admin package:** `POST /api/admin/service-packages` with code/name, monthly whole-VND unitPrice, durationMonths 6 or 12, learnerLimit >0, aiQuotaUnits >=0, aiPolicyVersionId required for positive quota, isActive. Verify `commercialVersion=7`, `pricingBasis=Monthly`, `isPurchasable`. GET and PATCH using the returned quoted ETag. Duration 1, zero seats or missing positive-quota policy must return field validation errors. Readable legacy packages remain not purchasable until fully configured.
3. **Organization quote:** choose own active named/addressed Building. POST `/api/billing/quotations`, Idempotency-Key unique, body `{ "items": [{ "buildingId": "...", "servicePackageId": "...", "purchaseAction": "New" }] }`. Verify total price per line equals monthly price times duration before discount, snapshot capacity/quota, Draft and ETag. Same key/body must replay; changing body with the same key returns409. PUT is not used: edit Draft through PATCH with If-Match.
4. **Admin Issue:** GET the quotation and copy its ID, line IDs and quoted ETag. POST `/api/admin/quotations/{id}/issue`, If-Match, body `{ "taxAmount": 0, "terms": "Test terms", "validUntil": "<UTC payment deadline>", "items": [{ "quotationItemId": "<line ID>", "startsAt": "<future UTC service start>" }] }`. Supply every line once. Payment deadline cannot be after the earliest start. EndsAt is calculated using calendar months. Ongoing Renewal starts at the last committed period end; expired Renewal needs an explicit future start. Invalid policy coverage, stale ETag, Upgrade or invalid term is rejected. Changing catalog later must not alter the Issued quote.
5. **Organization Accept:** POST `/api/billing/quotations/{quotationId}/accept` with the **new** ETag, not Building ID. Acceptance alone does not charge/provision. POST `/api/payments/payos/create` with quotationId and Idempotency-Key. Read checkoutId through GET checkouts, and paymentRequestId through GET requests. Creating overlapping open checkouts for the same Building/period must return409 `PAYOS_SERVICE_PERIOD_RESERVED`. A timeout does not free a reservation. Only provider-confirmed unpaid cancellation/expiry can release it.
6. **Payment/provisioning:** on an explicitly authorized provider test, inspect Paid/Applied separately from each provisioning line. Verify entitlement period/capacity and quota provenance agree with the frozen quote. Quota expires with its own interval and does not roll over. Repeated webhook/create/reconcile must not add entitlement/grant. A late payment still appears Paid/Applied and may be NeedsReconcile; return URL status never changes money. This implementation run used fake providers only.
7. **Publish:** enable `Publishing__Enabled=true` only after gate migration and smoke checks. Use a Built release with an active matching Training, accepted current package/manifest, Passed validation without blockers, exact revision/version confirmation, approved content/rubric and currently effective paid Building service. POST `/api/releases/{releaseId}/publish` requires Idempotency-Key, has no body and returns200 ReleaseResponse. Same actor/key/input replays the original response with no extra audit, even after revoke, without republishing; GET shows current state. Trial alone returns409 `BUILDING_ENTITLEMENT_REQUIRED`; stale readiness/approval/compatibility returns its409 code; a fresh operation on Revoked cannot publish. Disabled feature remains503. See [publish/review checks](publish-review-manual-test.md). Real Unity/package validation and learner launch are separate acceptance.
8. **Audit:** Admin GET list with targetEntity/action/actor/organization/target/correlation and UTC range, then detail. Verify root metadata and safe changes only. Secret/PII/raw JSON/support content must be absent. Non-admin403; numeric enum, timezone-less range, >90days or pageSize>100 returns400.
9. **Operations:** compare Admin and OrganizationUser GET responses. Platform includes accounts/organizations/buildings and historical created counts; organization includes only own Building/processing plus caller-created tickets, no accounts. `processingJobs` identifies kind and current status for jobs created in range. Confirm zero buckets and `[from,to)` boundaries. These are not learner completion/revenue metrics.

The source inventory is regenerated from the captured OpenAPI, not manually counted. ETag/If-Match and idempotency headers must match actual HTTP behavior. Source/Docker tests can be checked off independently; deployment, frontend and real provider evidence remain pending.
