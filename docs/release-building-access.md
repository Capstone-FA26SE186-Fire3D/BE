# Built release and Building access

POST /api/releases requires OrganizationUser/PlatformAdmin, a live session family, Idempotency-Key, revisionId, scenarioVersionId, confirmationReviewId and candidateArtifactId. Server requires immutable content approval and Passed technical confirmation for that exact pair, accepted current ReleasePackage attempt and compatible manifest/package metadata. Optional legacy package fields must match accepted worker output. Metadata is derived from server records; URLs in this response are object keys, not browser/public URLs.

Release, package, provenance, matching Active Training, receipt and audit commit together. Same actor/key/input replays the original Built response; different input returns 409 IDEMPOTENCY_KEY_CONFLICT. Another key for that pair returns RELEASE_ALREADY_EXISTS. Built does not prove a real Unity build. Publish uses the paid readiness/provenance gate when Publishing:Enabled=true; default rollout remains disabled (503). See billing-v7-rollout.md for409 prerequisites and authorized204 replay.

Building defaults Private. GET /api/buildings/{id}/access returns ETag "access-1". OrganizationUser in the tenant or PlatformAdmin can PATCH /access with { "visibility": "Public" }, POST /participation-code/rotate, or DELETE /participation-code, each with current If-Match. Missing/malformed/stale header: 428/400/412. Rotation returns a random code once; only its SHA-256 hash is stored. Changing visibility/code increments access revision and invalidates earlier grants. These actions are atomic with audit.

Trainee POST /api/buildings/{id}/participation/verify with { "code": "..." } binds access to caller and current revision. GET /api/buildings/{id}/trainings requires login even for Public. Trainee sees only Active Training with Published release and pinned Approved review, within schedule and with current Building access. OrganizationUser reads only their tenant; Admin has explicit platform scope. Listing never creates a seat, start permission or entitlement.
