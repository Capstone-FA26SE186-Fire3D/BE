# Built release and Building access

POST /api/releases requires OrganizationUser/PlatformAdmin, a live session family, Idempotency-Key, revisionId, scenarioVersionId, confirmationReviewId and candidateArtifactId. Server requires immutable content approval and Passed technical confirmation for that exact pair, accepted current ReleasePackage attempt and compatible manifest/package metadata. Optional legacy package fields must match accepted worker output. Metadata is derived from server records; URLs in this response are object keys, not browser/public URLs.

Release, package, provenance, matching Active Training, receipt and audit commit together. Same actor/key/input replays the original Built response; different input returns 409 IDEMPOTENCY_KEY_CONFLICT. Another key for that pair returns RELEASE_ALREADY_EXISTS. Built does not prove a real Unity build. Publish uses the paid readiness/provenance gate when Publishing:Enabled=true; default rollout remains disabled (503). Publish requires Idempotency-Key and returns 200 ReleaseResponse. See [publish/review acceptance](publish-review-manual-test.md) for error codes, replay and deployment prerequisites.

Building defaults Private. GET /api/buildings/{id}/access returns ETag "access-1". OrganizationUser in the tenant or PlatformAdmin can PATCH /access with { "visibility": "Public" }, POST /participation-code/rotate, or DELETE /participation-code, each with current If-Match. Missing/malformed/stale header: 428/400/412. Rotation returns a random code once; only its SHA-256 hash is stored. Changing visibility/code increments access revision and invalidates earlier grants. These actions are atomic with audit.

Trainee POST /api/buildings/{id}/participation/verify with { "code": "..." } binds access to caller and current revision. GET /api/buildings/{id}/trainings requires login even for Public. Trainee sees only Active Training with Published release and pinned Approved review, within schedule and with current Building access. OrganizationUser reads only their tenant; Admin has explicit platform scope. Listing never creates a seat, start permission or entitlement.

Migration 20261007100000_AddReleaseAndBuildingAccess adds access fields/grants, provenance/receipts and restricted SQL gates; it does not attest legacy releases. Deploy migration before binary. Native disposable PostgreSQL with actual migration history: approval denial, atomic/replay/race/audit rollback, restricted-role direct-DML denial, participation/rotate/revoke and Public/Private listing passed. Package output and Published state in tests are explicit fixtures, not production worker/publish acceptance. New migration not applied to Supabase in this task.

Publish rollout (#51): the publish gate is implemented (approval hash, readiness, paid entitlement, package/runtime, active Training; one 409 code per missing condition; Idempotency-Key replay; audit). It stays behind `Publishing:Enabled` (default `false`, env `Publishing__Enabled=true`) until the deployment database has every migration applied (`GET /health/ready` = 200) and the runtime catalog row for the target runtime exists. With the flag off, publish returns `503 PUBLISH_GATE_UNAVAILABLE`. Revoking a release archives its Trainings (migration `20261012160000_AddReleaseRevokeTrainings`); participation grants belong to the Building and are kept.

Release lookup (#53): `GET /api/releases?buildingId=&scenarioId=&status=&page=&pageSize=` lists releases newest first (`id`, `buildingId`, `scenarioId`, `scenarioVersionId`, `versionNumber`, `scenarioName`, `status`, `createdAt`, `publishedAt`, `revokedAt`); `status` is Built, Published or Revoked (other values 400). OrganizationUser sees only its organization, PlatformAdmin every organization. `GET /api/releases/{id}` adds `entitlement` — the Building service period covering now (`id`, `status`, `startsAt`, `endsAt`, `paid`, `learnerLimit`), or null; publish still re-checks a paid period. `GET /api/buildings/{id}/trainings` items add `releaseStatus`, `scenarioVersionId` and `reviewStatus` (always `Approved`: only Trainings pinned to an approved content review are listed).
