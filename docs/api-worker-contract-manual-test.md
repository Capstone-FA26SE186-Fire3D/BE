# Worker/API contract checks

Use a migrated disposable environment first. Deploy the four forward migrations in order (pending cleanup, Avatar cleanup, readiness live family, readiness audit changes), then the matching API/worker binary. The family-less readiness entrypoint fails closed. Grant-only changes revoke old direct queue/account writes; old workers must not be kept running. Supabase/Azure rollout and live S3/worker verification are separate from these source tests.

1. **Identify artifact:** GET `/health/version`; compare the deployed artifact commit/version, slot and worker startup logs with the intended build.
2. **Session:** log in as OrganizationUser or Admin as required. In Swagger authorize with the access token. Confirm/technical-reject and submit/approve/reject require the live token family; the client never sends a family in JSON. Logout-all, then retry a selected mutation with the old access token: expect `401` and no mutation. A newly logged-in session remains usable. The Docker concurrency test additionally covers a request that already passed middleware and waited for the actor lock.
3. **Catalog:** Admin creates/updates packages, quota policies and discounts with valid bodies. PATCH sends the current quoted ETag in `If-Match`. Missing/malformed/stale ETag gives `428/400/412`; revoked family gives `401`. Enterprise requests use a live OrganizationUser family and `Idempotency-Key`.
4. **Annotations:** GET `/api/revisions/{revisionId}/annotations`; copy response `ETag` including quotes. PUT the same route with `If-Match` and `{ "items": [] }`; expect `200` and a new ETag. Omit header: `428`; use `invalid`: `400`; reuse old ETag: `412`. Non-empty anchors must be present in accepted current Geometry provenance. The store uses the existing Geometry reference gate, not an absent `bim_facts` table.
5. **Preview:** GET `/api/buildings/{buildingId}/editor-preview?revisionId=...`. Complete accepted provenance plus a matching S3 object gives `Ready` and a five-minute signed URL. Missing object or wrong size gives `NotReady` with null URL. Test access denied/timeout on an isolated storage fixture: expect `503 PREVIEW_STORAGE_UNAVAILABLE`; no provider internals or URL. HEAD does not replace hash/QA checks.
6. **Readiness/approval audit:** confirm an exact pair; submit then approve/reject using the returned hashes and idempotency key. As Admin list `/api/admin/audit-logs?targetEntity=ScenarioVersion`, then GET one audit ID. New records show safe status/IDs/actor/times; no reason/content/token/PII. Recognized legacy metadata without the new marker keeps `changes: []`. Receipt replay must not append another audit.
7. **Pending cleanup:** seed only expired legacy pending records in an isolated database. Run with the actual API role: the cleanup gate may remove eligible accounts and bounded maintenance records, but verified accounts and accounts/organizations with business or audit history remain. OTP-before-registration creates no pending account to delete. API must not have general DELETE on users/organizations.
8. **Avatar recovery:** finalize/delete enqueue in the same transaction. With the runtime role, claim/retry cleanup through gates without queue DML. Protected object jobs stay queued; old leases cannot acknowledge newer claims. Fake S3 NotFound completes, temporary failure retries. Logs include job/attempt/error type/SQLSTATE, not object keys or provider payload.

Check results separately: source code, HTTP tests, PostgreSQL migration/grants/races, fake S3/worker tests, actual deployment/providers. Linux decoder tests must use a healthy runtime; a corrupt local SDK image is not an application decoder failure. Training analytics, learner lifecycle and real Unity acceptance remain outside this batch.
