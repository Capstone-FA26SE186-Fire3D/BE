# Scenario authoring and package builds

OrganizationUser operates only in their active tenant; PlatformAdmin has explicit platform scope. Every mutation rechecks the live actor, organization and Building under the lifecycle/Building locks. No implicit Guid.Empty tenant scope.

- `POST /api/scenarios` and `POST /api/scenarios/{id}/draft` require `Idempotency-Key` (1–128 characters, no whitespace/control characters). Same actor/key/input returns the existing ID; different input returns `409 IDEMPOTENCY_KEY_CONFLICT`.
- `GET /api/scenario-drafts/{id}` returns the PostgreSQL xmin as a quoted ETag. `PUT` and `POST .../snapshot` require that exact `If-Match`: missing 428, malformed 400, stale 412. Snapshot also requires an idempotency key; its receipt includes the original revision. Retry a lost response with the original key and ETag.
- Draft numbers and version numbers are allocated under a parent scenario lock, with database uniqueness as a second guard. State update/snapshot/receipt/audit are atomic; audit failure rolls back the operation.
- A version contains a canonical SHA-256 of its JSON state and an immutable full state snapshot. Updating or deleting a version is rejected by PostgreSQL. Author a new version to change content.

V7 snapshots require nonblank `learningObjectives` and `learnerInstructions`, plus an explicit rubric:

```json
{"schema_version":"1","pass_threshold":1,"criteria":[{"id":"exit","metric":"exit","mandatory":true,"weight":1,"operator":"gte","threshold":1}]}
```

Thresholds above are a test fixture, not a default grading policy. Criteria IDs must be unique; operator is gte/lte/eq, weight nonnegative, mandatory Boolean and threshold numeric. Spawn/hazard/scoring/routing structure remains validated. Optional `objectAnchors` must exist in accepted Geometry output metadata for the same revision. Nonempty `requiredCapabilities` must be supported by the specified active `runtimeVersion` catalog entry. Structural validation returns issues by JSON path and does not create geometry QA, readiness or approval.

`POST /api/scenario-versions/{id}/package-builds` accepts `{ "kind":"PlaytestPackage", "buildTarget":"Android" }` (or ReleasePackage) and an idempotency key. It returns 202 with jobId. `buildTarget` must be one a package worker serves (`ProcessingWorker:PackageBuildTargets`, default `Android`), otherwise 400 `BUILD_TARGET_UNSUPPORTED`: a job for another target would never be leased. A revision runs one job at a time (Geometry or package): while another job of the revision is Queued/Running the answer is 409 `PROCESSING_JOB_ACTIVE` with `errors.jobId` (BE#131); the same build input answers its existing job. The server pins verified IFC source ID/hash, immutable version/hash/rubric and target before outbox delivery. Worker claim returns this input and the immutable scenario snapshot; package outputs must include unity_package and manifest and match pinned target/runtime metadata. Only accepted outputs can be used downstream. A queued or mocked build is not evidence of a real Unity build.

Migration is additive: receipt table, draft-number unique index, nullable legacy version snapshot/rubric/learner fields, pinned job input and gates. Duplicate legacy numbering stops preflight; no legacy rubric/readiness is invented. Apply migrations before the binary. Tests used actual migrations on isolated PostgreSQL and fake worker outputs; Supabase and IFC/Unity providers remain unverified.

Manual test: create a scenario/draft with distinct keys; GET ETag; PUT a complete v7 state; GET fresh ETag; validate; snapshot with new key/current ETag; replay identical request; change key input to observe 409; submit package build and inspect processing status. Publish remains gated.

Geometry acceptance: object anchors come only from the current Succeeded Geometry attempt with a matching Passed validation run and no Error/Critical issues. A Succeeded worker job can carry Failed validation; it is not sufficient for validate/snapshot. Missing, failed, blocked or stale geometry returns ANCHOR_NOT_FOUND by path; snapshot rejects without creating a version/receipt. Forward migration20261007140000_RequirePassedGeometryAnchors repairs this check without changing legacy data. Warning-only Passed geometry remains usable.

## Organization work in progress (#152)

`GET /api/organizations/me/work-in-progress?limit=1` feeds the "continue authoring" card on the Building list without per-Building calls. OrganizationUser only (Trainee and PlatformAdmin 403, revoked session 401). Items are the caller's organization's scenario drafts on active, not deleted Buildings, newest save first (`scenario_drafts.updated_at`, set by every PUT), including drafts whose scenario already has snapshots. `limit` 1–5, default 1; anything else is 400 `VALIDATION_ERROR` with `errors.limit`. No drafts: `items: []`.

Item: `kind` (`ScenarioDraft`), `buildingId`, `buildingName`, `scenarioId`, `scenarioName`, `draftId`, `draftNumber` (the draft's own number within its scenario, shown as "Bản nháp vN"), `revisionId`, `latestVersionNumber` and `latestVersionReviewStatus` (NotSubmitted/Submitted/Approved/Rejected) of the scenario's newest snapshot or null, `updatedAt`. Drafts are mutable and versions immutable, so resuming opens the draft (`GET /api/scenario-drafts/{draftId}` for state and ETag) and never edits an approved version. Drafts, scenarios and Buildings are read with the API's existing SELECT grants; review status comes from `scenario_review_read_gate` (`States`), which rechecks the live session and tenant. No migration.

## Versioned editor contract `fet3d.editor/1` — 2026-10-11

Contract, JSON Schemas and shared fixtures: [contracts/editor/v1](../contracts/editor/v1/README.md). The .NET validator is authoritative.

- A draft body with `schemaVersion: "fet3d.editor/1"` is shape-validated on PUT and stored as sent, so GET → PUT → GET keeps every supported field (jsonb may reorder keys). Unknown fields, wrong types, non-finite numbers, invalid enums and duplicate IDs return `422 EDITOR_SCHEMA_INVALID` with `issues: [{code,path,message}]` (JSONPath). Partial drafts are allowed. Optional `libraryRefs` (max 50 `{versionId, kind, code?}`) records which Organization Library versions the author copied from (#88); it is provenance only and is part of the state hash.
- Malformed JSON returns `400 EDITOR_JSON_MALFORMED`; an unsupported `schemaVersion` returns `422 EDITOR_SCHEMA_VERSION_UNSUPPORTED`. A body without `schemaVersion` keeps the legacy typed shape and legacy validator; stored legacy drafts and snapshots are never converted and no unit or coordinate is assigned to them.
- The versioned draft pins `geometry.artifactId/sha256Hash` of the current accepted `preview_glb` artifact of its revision (current Succeeded attempt, Passed Geometry validation, no Error/Critical issue, versioned metadata). `objects[]` uses the discriminator `kind` (`Spawn`, `Hazard`, `Goal`, `Npc`, `BlockedElement`, `Equipment`) with `placement {floorId, position (floor-local metres), rotation (unit quaternion)}`, optional `anchorId` (IFC GlobalId of the pinned semantic mapping on the same floor), `capability {id,version}` and `parameters`.
- Kinds are placement categories only. Behaviour comes from `runtime_compatibility_catalog.capability_contracts` (`{version, objectKinds, parameters}` per listed capability), published by operators; nothing is seeded and Library equipment metadata does not enable a capability. `Hazard`, `Npc` and `Equipment` require a capability; parameters are validated against its closed parameter schema.
- Validate and snapshot run complete validation (at least one Spawn and Goal, rubric, learner fields, `timeLimitSeconds`, `runtimeVersion`) plus revision references: `GEOMETRY_NOT_ACCEPTED`, `FLOOR_NOT_FOUND`, `ANCHOR_NOT_FOUND`, `ANCHOR_FLOOR_MISMATCH`, `RUNTIME_NOT_SUPPORTED`, `CAPABILITY_NOT_SUPPORTED`, `CAPABILITY_VERSION_MISMATCH`, `CAPABILITY_KIND_UNSUPPORTED`. The database function `scenario_reference_issues` re-checks references inside the snapshot gate under lock. Snapshot of an invalid versioned draft returns `422 EDITOR_SCHEMA_INVALID` without creating a version or receipt.
- The snapshot keeps the validated state and its canonical hash. A derived projection fills the legacy configuration columns (`spawn_config`, `goal_config`, `fire_source_config`, `npc_config`, `blocked_elements`, `routing_config.goalObjectIds`, `time_limit_seconds`, `mode_policy`, seed/replan); `state_snapshot` stays authoritative.
- Known limit: a snapshot retry with the same key re-runs .NET validation before reaching the receipt; if references became invalid after the first snapshot (for example Geometry reprocessed), the retry returns 422 instead of replaying. GET the scenario versions to confirm the committed snapshot.

Migration `20261011090000_AddEditorContractV1` is additive: catalog column `capability_contracts` (default `{}`), projection trigger and a forward replacement of `scenario_reference_issues` that keeps its owner, ACL and legacy branch. Preflight stops if versioned snapshots already exist. Tests ran actual migrations on disposable PostgreSQL with fake worker outputs; structural validation is not geometry QA, and no real worker, Unity runtime or Supabase deployment was exercised.

## Initial draft, dry-run validation and QA history (#66)

**What "partial" means on PUT (#90).** Only `schemaVersion` is required at the root; every other root field may be omitted. A value that *is* sent must be complete at its own level, so the stored draft never holds half an element:
- each `objects[]` element needs `id`, `kind` and `placement` with `floorId`, `position {x,y,z}` and `rotation {x,y,z,w}` (`anchorId`, `capability`, `parameters`, `label` optional);
- `rubric`, when sent, needs `pass_threshold` and `criteria`; each criterion needs `id`, `metric`, `mandatory`, `weight`, `threshold`, `operator` (`description` optional); `schema_version` may wait until validate;
- `libraryRefs[]` elements need `versionId` and `kind`.
Completeness (Spawn/Goal present, `timeLimitSeconds`, `runtimeVersion`, objectives, instructions, rubric, capability contracts, anchors for blocked elements) is checked only by validate, validate-state and snapshot.

**Dry-run hash (#90).** `POST /api/scenario-drafts/{id}/validate-state` returns `stateHash` = lowercase hex SHA-256 of the exact UTF-8 request body bytes. Hash the string you send (`body = JSON.stringify(state)`; `sha256(utf8(body))`); Vietnamese text and any key order match because nothing is re-serialised.

**Floors and anchors (#90).** `GET /api/revisions/{id}/floors` returns `floors` and `semanticMapping` (anchor/node → `ifcGlobalId`, `floorId`, `semanticType`) whenever the accepted Geometry metadata satisfies the editor contract, even while the GLB object is not yet verified, without signing a URL. `editor-preview` returns the same fields and additionally a signed GLB URL once `Ready`.

**Draft list kinds (#90).** `GET /api/scenarios/{id}/drafts` items carry `stateKind`: `Uninitialized` (state still `{}`), `Versioned` (`schemaVersion` set) or `Legacy` (pre-editor typed shape); `schemaVersion` is null for the first and last.

**Initial draft contract.** `POST /api/scenarios/{id}/draft` creates a draft whose state is `{}`. The smallest state a client can PUT back with the returned ETag is the versioned document `{"schemaVersion":"fet3d.editor/1"}`: versioned drafts accept partial content and keep every supported field. A legacy body (no `schemaVersion`) must match the legacy typed shape (`spawnPoints`, `hazards`, `scoringConfig`, `routingConfig`), so new clients should start versioned. An incomplete draft is never treated as valid: validate, dry-run and snapshot report what is missing (for example `$.objects`, `$.timeLimitSeconds`, `$.runtimeVersion`, `$.learningObjectives`, `$.rubric`). The server does not insert defaults such as zero scores or empty arrays.

**Dry run.** `POST /api/scenario-drafts/{id}/validate-state` takes the same body as PUT and checks it against the draft's revision without storing it or changing the ETag. It runs the PUT shape check and the full validation; shape problems come back as issues (200, `isValid:false`) instead of 422. Response: `draftId`, `storedVersion` (unchanged), `stateHash` (SHA-256 of the checked JSON as received, so the client can tell which edit the issues belong to), `isValid`, `issues[{code,path,message}]`. Malformed JSON is `400 EDITOR_JSON_MALFORMED`; a non-object body is 400; a draft outside the caller's scope is 404. `POST /api/scenario-drafts/{id}/validate` keeps validating the stored draft.

**QA history.** `GET /api/revisions/{id}/validation-runs?jobId=&page=&pageSize=` lists every validation run of the revision, newest first: `id`, `processingJobId`, `jobKind`, `processingAttemptId`, `attemptStatus`, `artifactId`, `scenarioVersionId`, `scope`, `validatorVersion`, `outcome`, `isCurrent`, timestamps. `isCurrent` is true only for the accepted current attempt of a Succeeded job. Historical runs are for reading only; `GET /api/validation-runs/{id}`, `/processing-jobs/{id}/qa`, confirm-for-training, release and publish still use the current accepted attempt.

**Aggregated status.** `GET /api/revisions/{id}/readiness` (see [scenario readiness](scenario-readiness.md#resume-after-reload-53)) returns, in one request, the geometry job, its QA outcome, issue counts by severity, blockers, confirmations and `latestJobs` (newest job of each kind with its status). A Succeeded job is not a QA pass: read `outcome`, `blockerCount` and `missing`.
